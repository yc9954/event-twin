## 공개 Vercel → Brev/OpenShell 실연동

`node scripts/vercel-smoke.mjs`를 공개 URL에서 실행했다. 임시 합성 프로젝트를 만들며 실제 모델 호출 비용이 발생할 수 있다. 개인 쿠키·서버 키·원본 기록은 저장소에 포함하지 않는다.

- 공개 페이지: 로그인 없이 접속, 익명 서명 세션 시작.
- 실제 런타임: NemoClaw/OpenShell 내부 Node 앱과 NAT 프로세스.
- 모델: `nvidia/nemotron-3-super-120b-a12b`, OpenShell 관리형 추론 경로.
- 연결 검증: 도구가 반환한 새 무작위 토큰을 모델이 다시 반환하는 읽기 전용 왕복 성공.
- 실시간 대화: 실제 `get_project` 호출 성공. 스트림 이벤트 **302개**, 텍스트 delta **296개**, 최초 이벤트 약 **351ms**, 전체 약 **9.3초**. 한 번의 측정이며 성능 보장이 아니다.
- 실제 NAT **1.9.0** 상태 조회 및 저장된 16안 결과 감사 성공.
- 16개 후보 생성 → 16개 반복 시뮬레이션 결과 → 선택안 승인 → CRM 생성·적용 성공.
- 해당 합성 실행에서 CRM **6개 구역, 540개 회차**, 고객 등록 1건, 운영 관측 1건, 개선 제안 1건 생성.
- 새 요청에서 저장 버전과 고객 재조회, 내보내기 성공.
- 다른 익명 세션의 프로젝트 조회 **404**, 잘못된 Origin 변경 요청 **403**, 세션 초기화 전 API **409**.

마지막 성공 검사는 **모델 읽기 도구 + 명시적 로컬 계산/CRM 도구**를 결합한 하이브리드 종단 검사다. 모델이 모든 단계를 자율 계획·실행했다고 주장하지 않는다. CRM 적용은 이 앱 안의 실제 SQLite 운영 구조이며 외부 CRM SaaS 배포가 아니다.

## 관측된 외부 실패

같은 검수 중 NVIDIA 관리형 경로가 간헐적인 **502**를 반환했다. 연결 검사가 실패한 실행, 연결 검사는 통과했지만 대화가 실패한 실행이 각각 있었고 이후 종단 검사가 성공했다. 해당 실패를 숨기거나 로컬 모드로 자동 대체하지 않았다. 앱은 요청 전 5xx에 제한적으로 재시도하며, 이미 노출된 스트림이나 완료한 도구를 자동 재실행하지 않는다. 제공자 가용성·잔액·한도에 대한 SLA는 없다.

공개 샌드박스에서 Overpass 새 시설 조회는 연결에 실패했다. 별도 최소 읽기 요청에서도 연결 취소가 재현되었다. 기존 강의 샌드박스의 네트워크 정책을 변경하지 않았으며, UI는 실패와 기존 스냅샷의 수집 시점을 그대로 표시한다. 저장된 실제 OSM 지형·시설·거리 계산은 사용할 수 있지만 최신 시설 조회를 검증 완료로 간주하지 않는다.

## Claude fallback 배포·실호출 검증

- 기본 제공자는 **NVIDIA/Nemotron**으로 유지했다. 별도 **Anthropic Claude Sonnet 4.6** 키를 비공개 환경 파일에 설정하고 네이티브 SDK를 사용한다. 키·쿠키·프로젝트 원본은 저장소에 포함하지 않았다.
- OpenShell의 Anthropic outbound 차단을 재현한 뒤, 앱 Node 바이너리에 한정된 REST 경로 규칙 `event-twin-claude`를 추가했다. 정책 **v3 활성화** 후 같은 샌드박스의 실제 `/v1/messages` 호출 **HTTP 200**과 짧은 응답을 확인했다. 기존 NVIDIA 관리형 추론·TLS 검증은 유지했다.
- `scripts/claude-fallback-smoke.mjs --confirm-live-api`: **NVIDIA 실패만 의도적으로 주입**하고 Claude는 실제 API를 호출했다. 프로젝트 DB·고객·사진을 사용하지 않는 읽기 전용 합성 검사다. Claude가 `get_project`를 한 번 호출한 뒤 그 결과에만 존재하는 새 무작위 검증값을 반환했다. **2026-09-28 23:28 KST**, 14.2초, fallback 이벤트 1개, 공개 텍스트 delta **221개**, 도구 왕복 검증 통과. 이는 실제 NVIDIA 장애 발생의 증거가 아니라 장애 대응 코드 + 실제 Claude 추론의 결합 검증이다.
- 초기 Claude 검사에서는 모델이 참고자료와 현재 요청을 혼동해 도구를 호출하지 않았다. 이를 성공으로 처리하지 않았고, 참고자료 종료·현재 사용자 요청을 명시적으로 구분하고 권한 가이드의 모호한 표현을 수정한 후 위 검사를 통과했다. 임의 코드·승인·연락처 전송을 허용한 수정은 아니다.
- 공개 Vercel 재검사: 실제 NVIDIA 연결 검사의 새 검증값 왕복 성공, 모델 `get_project` 호출과 공개 delta **267개**, 16안 생성·계산, NAT 감사, 오너 승인, CRM **6구역·540슬롯**, 합성 고객·관측·개선 가설 저장 흐름 통과. 다른 세션 404, 외부 Origin 403, 초기화 전 요청 409 경계 유지.
- UI에서는 새 NVIDIA + Claude 제공자 조합의 동의를 요구하고 실제 모델 전환·이유를 표시한다. 서버 테스트는 이전 NVIDIA 단독 동의 거절과 Claude 실제 제공자·모델·fallback 기록 저장을 확인한다. 이미 출력한 답변·취소·모델 거절·길이 제한에는 자동 전환하지 않으며 완료한 도구를 처음부터 재실행하지 않는 회귀 검사도 통과했다.
- NVIDIA 제공자의 간헐 오류 자체가 해결됐다고 주장하지 않는다. Claude fallback으로 앱 가용성을 보완하며, Anthropic도 잔액·한도·서비스 상태에 따라 실패할 수 있다.
